# E-001 implementation plan

1. Add a diagnostic observer to the existing paired match runner. Keep it optional and leave the normal summary metric and action-time enforcement unchanged. Stream one JSONL row per two-hand block and one row per public decision, with no hole cards, board cards, deck state, or RNG internals. Give a control decision its table-visit and fallback metadata directly from `RestrictedAgent::act` after its existing policy lookup. This metadata must not change its action or RNG consumption.
2. Test exact reconciliation of diagnostic block returns, action counts, timeouts, and fallback counts with the match summary. Test preservation of each agent's private packet and the board under the button swap, deterministic diagnostic traces for identical seeds, and policy action equality under changed opponent hole cards and future cards with the same observation and policy RNG.
3. Commit and rebuild a clean development binary. Verify the frozen artifact and the original benchmark files by hash. Run only the 30 matches predeclared in `experiments/e001.json`: three roots, five opponents, two independently instantiated arms, 10,000 hands per arm. Use the same root and block index in both arms; retain every report and diagnostic file, including failures.
4. Check every expected block and decision row. Compute per-opponent treatment-minus-control intervals from paired block differences. For the primary result, average the three strong-opponent differences within each shared `(root_seed, block)` cluster, then compute a 95% normal-standard-error interval over those 15,000 independent clusters. Report all opponents, candidate action/fallback mix by street and seat, pot bands, timeouts, illegal actions, latency, runtime, hashes, and limits.

The frozen policy, equity implementation, game engine, opponent agents, training, final seeds, and existing reports are outside this experiment's edit scope. E-001 diagnoses the learned-table contribution on development data; it cannot promote a policy or satisfy Gate E.
